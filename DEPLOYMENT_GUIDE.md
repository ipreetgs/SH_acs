# Production Deployment & Security Strategy\n\n## 1. ESP32-S3 Firmware Security (`/firmware`)\nTo ensure commercial viability, the device must be cryptographically locked before shipping. We implement these features natively via `idf.py menuconfig` -> Security features.\n\n### 1.1 Secure Boot V2\n- Enforces that only signed code boots (preventing rogue firmware).\n- Generates RSA-3072 signature keys.\n\n### 1.2 Flash Encryption\n- Protects Wi-Fi credentials and the NVS state.\n- **Action:** Set to `Release` mode. Disables plaintext JTAG debugging and UART downloads.\n\n### 1.3 Matter DAC (Device Attestation Certificate)\n- Replaces the test CA Certificates with Production-signed certificates securely written to a specific `phy_init` or NVS partition to pass Apple/Google Home authentication.\n\n---\n\n## 2. Cloud Infrastructure Deployment (`/backend`)\nThe NestJS system requires **zero-downtime** deployments via Docker.\n\n### Docker Compose Overview\n1. **`postgres-db`**: The canonical persistence store for Users, Devices, and Telemetry.\n2. **`api-backend`**: Multi-instance Node.js backend to handle REST and real-time WebSockets.\n\n### Scaling WebSockets\nSince WebSockets require persistent connections between the Flutter App and the nest Backend -> ESP32, as we scale, NestJS integrates **Redis Adapter (`@nestjs/platform-ws`)** to syndicate messages across multiple pod instances.\n\n---\n\n## 3. Continuous Integration Flow\n\n1. **App (Flutter):** GitHub Actions -> Fastlane -> App Store / Google Play.\n2. **Firmware:** GitHub Actions -> `idf.py build` -> Outputs `firmware.bin` -> Automatically uploads the `.bin` to the Nested S3 bucket acting as the backend OTA distribution point. Changes database `FirmwareOTA` table to alert clients automatically.\n
